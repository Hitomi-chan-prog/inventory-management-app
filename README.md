# ストックノート — 在庫管理・発注アラートWebアプリ

HTML・CSS・JavaScriptで開発する、フレームワークを使わない学習・ポートフォリオ用アプリです。

## 現在の範囲：開発ステップ1

仮データで在庫一覧、商品登録／編集、商品詳細、入出庫・取消履歴を表示します。一覧・詳細から入庫／出庫ダイアログ、履歴から取消ダイアログを開けます。検索・要発注絞り込み・履歴の商品／種別絞り込みも試せます。

**保存・実際の在庫更新・取消・CSV出力・IndexedDBは未実装です。** 確認ボタンはデモメッセージを表示するだけです。予定在庫は参考表示で、在庫不足などの業務判定はまだありません。再読み込みすると仮データの画面に戻ります。

## 起動方法

リポジトリのディレクトリで次を実行します（Python 3が必要）。ビルドやnpmインストールは不要です。

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

ブラウザでローカルサーバーのポート8000を開いて確認してください。停止はターミナルでCtrl+C。VS CodeのローカルHTTPサーバー拡張からも起動できます。依存する外部ライブラリ・外部フォント・APIはありません。

## JavaScriptの読み方

1. `products`・`movements`・`cancellations`は表示専用の配列です。商品ID、元取引IDで関連付けています。DBの実装ではなく、履歴も全件分の台帳ではありません。
2. `renderRoute()`はURLの`#inventory`や`#product/p1`を読み、対応する表示関数を呼びます。`hashchange`はURLのこの部分が変わった時のイベントです。ブラウザの戻る・進むでも切り替わります。
3. `screen.innerHTML`で画面の中身を差し替えます。フォームを離れると未保存入力は消えます。将来、入力離脱の確認を検討します。
4. `filter()`は条件に合うデータを選び、`map()`はデータを表示用HTMLに変換します。検索条件は在庫一覧の再描画に使い、ダイアログを閉じても残ります。
5. クリックは親の`screen`で受け取り、`data-operation`から入庫・出庫・取消を判断します。動的に作ったボタンにも対応する「イベント委譲」です。
6. `showModal()`でダイアログを開き、`close()`で閉じます。Escapeでも閉じ、元のボタンへフォーカスを戻します。
7. `preventDefault()`はフォーム送信によるページ移動を止めます。今は確認メッセージだけを出し、配列も在庫も変更しません。
8. `required`・`min`・`step`で基本入力を確認します。取消理由は空白だけの入力も拒否します。`escapeHtml()`は文字列をHTMLとして実行させず表示するための処理です。実際の保存時の検証は後の段階で追加します。

## レビュー用操作例

- 在庫一覧で商品名・コードを検索し、「要発注のみ」を切り替える。
- 一覧から入庫・出庫を開き、予定在庫とデモ表示を確認する。
- 商品名を押して詳細へ進み、編集・入出庫・商品別履歴を確認する。
- 商品登録で入力し、確認後も保存されないことを確認する。
- 履歴で取消を開き、取消理由の空欄・空白のみ・通常入力を確認する。
- 取消済み履歴の理由・日時を確認し、取消ボタンが無効であることを確認する。
- PCとスマートフォン幅で確認する。スマートフォンの在庫一覧はカード形式、履歴の表は横スクロール対応。

## 開発管理

作業ブランチ：`feat/screen-skeleton`（`origin/main`から作成）。コミット・プッシュ・PR作成は利用者の承認後に行います。

PRタイトル案：`画面の骨組みと仮データによる在庫管理デモを追加`

PR説明案：在庫一覧・商品登録／編集・詳細・履歴と、入庫／出庫／取消ダイアログを追加。PC・スマートフォンに対応し、仮データで遷移と入力を確認できる。永続化・在庫更新・CSVは対象外。検証内容は`docs/test-plan.md`参照。
